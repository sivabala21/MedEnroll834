# 02. Business Problem

## Business problem

Healthcare enrollment processing relies on timely, accurate HIPAA 834 transactions. The current workflow uses a chain of legacy tools and scheduled jobs.

An inbound 834 file arrives in a designated folder. An EDI process converts the transaction into a proprietary file. An ECA process evaluates each member and assigns a plan. The process generates a keyword file for the FACETS platform. FACETS then loads the enrollment result.

The current implementation uses Tidal scheduling, SSIS, DataStage, .NET, TTK file movement, Bash validations, and W2K. Each handoff adds operational dependencies and failure points.

### Current constraint

An observed workload of approximately 300,000 records takes nearly one hour. Database locks and single-machine processing can limit throughput. Investigating failures across several tools can delay recovery.

### The three-V challenge

#### Velocity

Enrollment changes require prompt processing. Long batch windows delay downstream availability and operational response.

#### Volume

Large 834 files create pressure on serial processing and shared databases. The solution must scale without extending the batch window.

#### Variety

834 transactions contain varying member, employer, subscriber, group, and plan information. The pipeline must validate differences without losing source traceability.

### Business objective

The prototype shows how a modern data platform can address these constraints. It improves throughput, observability, recovery, and analytical access. It also provides a practical modernization blueprint for stakeholders.
