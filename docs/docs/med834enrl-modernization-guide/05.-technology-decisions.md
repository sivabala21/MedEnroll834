# 05. Technology Decisions

## Technology decisions

This prototype replaces fragmented, serial processing with scalable platform capabilities. Each technology addresses a specific legacy constraint.

### Orchestration: Apache Airflow

Airflow schedules, coordinates, and monitors pipeline tasks. It makes dependencies, retries, and run status visible in one interface.

Airflow improves on isolated Tidal schedules and tool-specific logs. Modern data teams use it for code-based, observable workflow orchestration.

Databricks Workflows remains a valid alternative for Databricks-only orchestration. This prototype uses Airflow to demonstrate platform-independent orchestration.

### Processing: Databricks and PySpark

PySpark distributes parsing, validation, and transformation across a compute cluster. It supports larger workloads without relying on one machine.

Databricks provides managed Spark, notebooks, jobs, governance, and SQL capabilities. This reduces infrastructure work while supporting collaborative data engineering.

### Storage: Amazon S3, Parquet, and Delta Lake

Amazon S3 provides durable, low-cost object storage for source and pipeline data. Parquet provides efficient columnar storage for analytics workloads. Delta Lake adds ACID transactions, schema controls, and version history.

Together, these tools improve traceability over proprietary intermediate files. They support reliable replay, incremental processing, and scalable reads.

### Operational database: PostgreSQL

PostgreSQL stores operational enrollment records after transformation. Bulk loading and upsert patterns support controlled downstream delivery.

The database serves transactional needs. It does not replace the analytical lakehouse.

### Analytics: Databricks SQL and Genie

Databricks SQL queries Gold-layer datasets and powers dashboards. It gives operations and business users timely enrollment visibility.

Genie supports natural-language access to governed analytical data. It requires curated datasets, approved terminology, and controlled permissions.

### Portfolio value

The project demonstrates ingestion, distributed processing, data modeling, and orchestration. It also demonstrates testing, observability, security, and measurable performance engineering.
