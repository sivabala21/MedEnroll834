## Modern architecture

The target architecture uses cloud storage, distributed processing, and managed orchestration. It separates operational enrollment delivery from analytical consumption.

### Architecture flow

1. Amazon S3 stores inbound 834 files and immutable raw copies.
2. Airflow starts and monitors the ingestion workflow.
3. Databricks and PySpark parse, validate, and normalize transactions.
4. Delta Lake stores Bronze, Silver, and Gold datasets.
5. PostgreSQL receives operational enrollment records through controlled bulk loads.
6. Databricks SQL serves dashboards and governed analytical queries.

The conceptual model maps enrollment entities to these data paths. It includes member, employer, subscriber, group, benefit plan, and reporting relationships.

### Operational path

PySpark extracts enrollment transactions from raw 834 files. Validation rules identify structurally invalid or incomplete records. Plan-assignment rules enrich valid member records. PostgreSQL stores the operational output for downstream integration.

### Analytical path

The same validated data feeds the medallion architecture. Bronze preserves raw data. Silver provides normalized and quality-checked data. Gold provides curated reporting and analytical datasets.

Databricks SQL dashboards expose enrollment metrics and pipeline outcomes. Genie can provide governed natural-language exploration of approved analytical data.

### Reliability controls

File identifiers and run metadata support idempotent processing. Invalid records are stored with rejection reasons. Airflow retries transient failures and records task-level status. Delta Lake supports reliable reads, writes, and historical data management.
