# 01. Project Overview

## Project overview

MED834 is a modernization prototype for healthcare enrollment processing. It models a production-style pipeline for inbound HIPAA 834 transactions.

The prototype demonstrates a faster and more reliable operating model. It does not use production member data.

### Objectives

* Handle high-volume enrollment files through distributed processing.
* Preserve raw source data and track every transformation.
* Serve both operational enrollment processing and analytical reporting.
* Demonstrate modern data-engineering practices in a portfolio-ready project.

### Conceptual model

The conceptual model separates enrollment processing from analytical data consumption. Member, employer, subscriber, group, plan, and benefit-plan information drive enrollment decisions.

Inbound 834 transactions enter an operational processing pipeline. The pipeline validates and normalizes each enrollment record. Valid records support operational loads and curated analytics. Rejected records enter a controlled remediation path.

The supplied conceptual model belongs with this overview and the modern architecture. It illustrates operational and analytical data paths around enrollment processing.

### Target workflow

1. Receive an 834 file from a federal or external source.
2. Land the original file in Amazon S3.
3. Parse, validate, and normalize member enrollment transactions with PySpark.
4. Apply plan-assignment business rules.
5. Load operational enrollment data into PostgreSQL.
6. Publish curated Delta tables for analytics and dashboards.

Airflow coordinates the end-to-end workflow. Databricks provides scalable processing, storage, and SQL analytics.

### Design principles

The pipeline is idempotent and supports incremental processing. Invalid records are quarantined with actionable rejection reasons. Every run emits metrics, logs, lineage signals, and audit metadata.

### Success measures

The prototype targets the legacy system's velocity, variety, and volume constraints. Benchmarking compares throughput, reliability, and operational effort. The expected outcome is faster delivery of trusted enrollment data.
